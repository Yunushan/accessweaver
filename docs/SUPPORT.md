# Local support summary

In Settings, **Export support summary** explicitly downloads the authenticated local core's metadata-only JSON. Nothing is uploaded. The report contains build identity, profile counts grouped by known engine, foreground state and log-line count, and workflow state with error/result-presence flags. It excludes profile and job identifiers, names, paths, arguments, targets, referenced files, raw logs, results, error details and session credentials. It does not inspect vendor services or establish connectivity.

Each export owns one request in the current Settings view and authenticated session. Leaving Settings, changing session or mode, or changing the observed connection state cancels that request. A late response cannot download a report, publish an old error or release a newer export's busy control. Start another export explicitly; requests are never replayed automatically. These browser controls cannot retract bytes already downloaded.

The browser reads at most 16 KiB of strict UTF-8 JSON under a 12-second request timer and validates the metadata-only report schema before creating a download. Failed, malformed, oversized or incomplete responses create no partial file and display fixed local feedback rather than server error details. This bound covers the browser response; it is not a disk quota, native I/O deadline or audit guarantee.

A previously authenticated core can still provide a summary after profile loading fails. Profile counts then read `unavailable` with a null total, rather than zero. Browser-only editing has no core summary. The recorded profile-editing desktop continues to deny support export; this feature adds no audit producer or managed audit enforcement.

Controlled browser-logic tests cover retained ownership, session/navigation/mode/connection invalidation, delayed success and failure during a newer export, body limits, timeout and private-error omission. A separate real-browser fixture serves only static assets and synthetic API replies, verifies actual request cancellation and one current download, and starts no product process. The optional `ACCESSWEAVER_SUPPORT_INTEROP` source fixture validates actual Go API responses against the browser validator and export flow with exact source and payload hashes. These checks do not qualify installed-product support procedures or vendor cleanup.
