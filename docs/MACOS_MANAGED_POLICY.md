# macOS managed-policy implementation

Status: native file/ACL inspection and atomic directory-publication primitives are implemented with native tests. Machine policy loading, administrator transactions, protected input validation and launch-environment integration are not activated yet. macOS continues to report unsupported machine enforcement until those paths and their acceptance tests are connected. This work does not promote a readiness gate.

## Native protection contract

`internal/darwintrust` uses descriptor-relative, no-follow opens through the maintained `golang.org/x/sys/unix` bindings. A protected object must have the expected owner (root in runtime callers), no group/other POSIX mutation bits or set-ID bits, the required directory/regular-file type and local APFS semantics. Regular files must have exactly one hard link. A descriptor-bound identity comparison rejects replacement between inspection and opening. Special files are rejected before reading; path aliases, symbolic links and unsupported filesystem/ACL models are refused.

POSIX modes alone do not establish macOS protection. Native extended ACLs are read from the opened descriptor with the [Apple ACL API](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/acl_get_fd_np.3.html). The independent ACL copy is validated and bounded to 128 entries. Deny entries and explicit read/search/read-metadata permissions may remain; every allow entry containing mutation or unknown rights is refused, including grants to otherwise trusted principals. This conservative rule avoids interpreting directory-service membership as endpoint trust. Readers never remove an existing object's ACL. A separate creation-only helper clears inherited ACLs on exclusively created private product objects before applying the intended published modes. It sets the native no-inherit flag so a later publication rename cannot restore a removed inherited read denial.

Extended-ACL and directory-rename calls use the fixed `/usr/lib/libSystem.B.dylib`, with explicitly typed nonvariadic function signatures. Native failures remain errors. A locked OS thread keeps the foreign call and errno lookup together; ACL memory is freed on every path. The project pins purego v0.11.2 and x/sys v0.49.0 with module hashes and records their licenses. These maintained dependencies require source Go 1.26 or newer; the existing native CI compiler remains pinned to Go 1.27.3. No CGO or platform C compiler is required for the trust tests.

The rename primitive exposes only exclusive initial publication and atomic directory exchange through `renameatx_np`. It takes two distinct single-component names under one verified parent descriptor. It performs no cleanup and has no copy/delete fallback. Its eventual transaction caller must hold a protected writer lock, check both directory identities, allowed layouts and raw preimages, sync both records and their staging directory before publication, sync the parent afterward, and preserve unexpected or independently changed displaced contents. A post-publication sync or cleanup failure must retain the known committed outcome.

## Native validation

Owned temporary fixtures exercise ordinary protected files, wrong owners, mutation modes, links, FIFOs, bounded names, actual extended-ACL mutation grants with unchanged POSIX modes, safe read/deny ACLs, clearing inherited deny ACLs on new objects, exclusive creation, nonempty directory exchange, held old directory descriptors and failed-publication preservation. They invoke only the fixed OS `chmod` on their own objects and do not change existing system configuration.

A read-only preflight checks `/`, `/Library` and `/Library/Preferences` on both hosted Mac architectures, including actual owner/mode, local APFS and extended ACLs. CI and preview retain `darwin-trust-preflight-ARCH` records with source, compiler and host architecture. The additional native step builds and runs with `CGO_ENABLED=0`. Compilation on a different OS does not prove these behaviors; inspect the exact source-bound native result.

## Required remaining integration

The proposed fixed parent is `/Library/Preferences`, with a product-owned policy directory below it. User preferences, environment variables, working directories and browser input must never select this authority. Native readers and writers must apply the same protections to all ancestors and both installation/acceptance records.

Complete root-only installation/update/rotation/recovery, atomic paired storage, required acceptance history, monotonic revision enforcement after primary corruption, bounded consistent readers, crash/abort cleanup, protected Mach-O/configuration inputs and a sanitized managed child environment. Add guarded disposable native root/ordinary-user tests for the actual fixed source and API/CLI guards before activating support. Existing version-one offline preparation does not establish native enrollment. Service authorization, generated inputs, independent revision escrow, full damaged-storage recovery, MDM delivery, signed distribution/notarization, endpoint lifecycle and physical power-loss qualification remain separate open requirements.
