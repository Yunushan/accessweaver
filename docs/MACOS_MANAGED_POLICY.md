# macOS managed-policy implementation

Status: partial macOS amd64/arm64 machine-policy loading, root-only install/update/key rotation/recovery, paired accepted history, protected foreground inputs and a sanitized child environment are connected. Native enrollment qualification for this candidate must come from the exact source-bound Intel and ARM CI results below. Source cross-compilation and the earlier owned-fixture results do not establish that qualification. Complete enterprise deployment remains open; this change does not promote a readiness gate.

## Native protection contract

`internal/darwintrust` uses descriptor-relative, no-follow opens through the maintained `golang.org/x/sys/unix` bindings. A protected object must have the expected owner (root in runtime callers), no group/other POSIX mutation bits or set-ID bits, the required directory/regular-file type and local APFS semantics with ownership enabled. Mounts with [Apple's MNT_IGNORE_OWNERSHIP flag](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/mount.h) are refused; filesystem identity alone cannot establish that ownership is enforced. Regular files must have exactly one hard link. A descriptor-bound identity comparison rejects replacement between inspection and opening. Special files are rejected before reading; path aliases, symbolic links and unsupported filesystem/ACL models are refused.

POSIX modes alone do not establish macOS protection. Native extended ACLs are read from the opened descriptor with the [Apple ACL API](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/acl_get_fd_np.3.html). On a held valid descriptor, Apple's `acl_get_fd_np` reports `ENOENT` when the extended ACL property is absent; POSIX/owner/type/link/filesystem checks still apply. Interrupted read-only ACL inspections repeat the complete inspection at most three times; persistent interruptions, timeouts and all other native failures are refused. Writes/publication are not retried by this reader. The independent ACL copy, when present, is validated and bounded to 128 entries. Deny entries and explicit read/search/read-metadata permissions may remain; every allow entry containing mutation or unknown rights is refused, including grants to otherwise trusted principals. This conservative rule avoids interpreting directory-service membership as endpoint trust. Readers never remove an existing object's ACL. A separate creation-only helper clears inherited ACLs on exclusively created private product objects before applying the intended published modes. It sets the native no-inherit flag so a later publication rename cannot restore a removed inherited read denial.

Extended-ACL and directory-rename calls use the fixed `/usr/lib/libSystem.B.dylib`, with documented integer/pointer signatures through the pinned purego `SyscallN` implementation. Its maintained Darwin trampoline captures errno inside the foreign call, before Go scheduling/allocation can overwrite thread-local state. A later separate errno lookup is not used. Error codes are interpreted at the native C-int width. `SyscallConn.Control` pins the descriptor through each operation; direct pointer arguments follow the native-call library's allocation-lifetime contract, and ACL memory is freed on every path. Native failures remain errors. The project pins purego v0.11.2 and x/sys v0.49.0 with module hashes and records their licenses. These maintained dependencies require source Go 1.26 or newer; the existing native CI compiler remains pinned to Go 1.27.3. No CGO or platform C compiler is required for the trust tests.

The rename primitive exposes only exclusive initial publication and atomic directory exchange through `renameatx_np`. It takes two distinct single-component names under one verified parent descriptor. It performs no cleanup and has no copy/delete fallback. The transaction caller must hold a protected writer lock, check both directory identities, allowed layouts and raw preimages, sync both records and their staging directory before publication, sync the parent afterward, and preserve unexpected or independently changed displaced contents. A post-publication sync or cleanup failure must retain the known committed outcome.

## Native validation

Owned temporary fixtures exercise ordinary protected files, wrong owners, mutation modes, links, FIFOs, bounded names, actual extended-ACL mutation grants with unchanged POSIX modes, safe read/deny ACLs, clearing inherited deny ACLs on new objects, exclusive creation, nonempty directory exchange, held old directory descriptors and failed-publication preservation. They invoke only the fixed OS `chmod` on their own objects and do not change existing system configuration.

A read-only preflight checks `/`, `/Library` and `/Library/Preferences` on both hosted Mac architectures, including actual owner/mode, local APFS, native mount flags/ownership-enabled semantics and extended ACLs. CI and preview retain `darwin-trust-preflight-ARCH` records with source, compiler and host architecture. The additional native step builds and runs with `CGO_ENABLED=0`. Compilation on a different OS does not prove these behaviors; inspect the exact source-bound native result.

## Paired native storage

The internal macOS transaction stages a version-two installation and its exact accepted-history record in one private, exclusively created directory. Both records are bounded, protected and synced before the directory becomes public. The file, candidate directory and post-publication parent use fsync plus the native F_FULLFSYNC drive-cache flush request, with descriptor pinning and no error fallback; see [Apple fsync semantics](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/fsync.2.html). Successful calls do not replace actual power-loss qualification. Initial publication is exclusive; updates exchange the two directories atomically. Readers open both records through one held generation and recheck its active identity, with at most three attempts. Missing acceptance history is an error even when a legacy version-one preparation is present.

A protected, empty mode-0600 coordination file serializes cooperating writers while leaving readers available. Before update publication, the directory identities, allowed entries and exact raw preimages must still match. A committed outcome survives a later parent-sync or cleanup error. Close removes only its known staging/displaced identity and exact record bytes; changed, partial or unrelated objects remain for administrator inspection. These checks do not authorize arbitrary root writers or defeat an administrator restoring the entire store.

Root-only native entry points use this transaction; the machine reader always requires both records. Owned fixtures exercise the shared installation/update/recovery signature and revision rules, initial-publication collisions, mandatory history, stale counters, links and mutation permissions, competing writers, concurrent readers and conservative cleanup. A separate owned-fixture process test sends SIGKILL after complete staging and after successful publication for both initial enrollment and updates. It checks the exact active pair, OS release of the same coordination-file lock, a subsequent signed transaction and preservation of independently changed abandoned bytes and unrelated objects. Source-bound native CI must establish whether these cases pass; they do not exercise termination inside a write, rename or sync, the root machine namespace, or physical power loss. An additional 45-case owned-fixture matrix stops after actual transaction operations: lock acquisition, private directory creation, each record creation/write/mode/fsync/full-sync/close, candidate protection/sync, publication before in-memory outcome recording, parent sync and displaced cleanup. A private in-package observer makes those boundaries deterministic; runtime constructors always pass nil, with no configuration or environment switch. Each case verifies the exact visible generation, writer-lock identity/release, a subsequent signed transaction and preservation of independently changed empty/partial/complete abandoned data. These boundaries are still outside individual kernel calls and do not simulate a lost drive cache. Native publication ordering still needs full crash-process and physical power-loss qualification. Automatic reclamation after a process exit, full damaged-storage recovery and independently anchored revision history remain open; the transaction does not guess the provenance of abandoned directories.

The owned-fixture returned-error suite additionally exercises 19 install/update/rotation/recovery cases with real closed candidate/parent/lock descriptors and independently changed displaced contents. It verifies that errors before publication preserve the exact old state, while errors after publication retain a valid signed pair and `committed: true`. A fresh writer must reacquire the same coordination-file identity; unpublished requests can be explicitly retried, published requests must fail replay, and retained data must survive either attempt. These native cases require exact-source CI results. They cover invalid handles and cleanup refusal, not hardware I/O faults, storage exhaustion or a privileged endpoint recovery procedure.

## Native source, inputs and child environment

The fixed authority is `/Library/Preferences/AccessWeaver`, containing `installation.json` and `acceptance.json`. The private coordination file is `/Library/Preferences/.accessweaver-policy.lock`. Every ancestor and record must satisfy the native protection contract. User preferences, environment variables, working directories and browser input cannot select this source. An absent directory leaves the endpoint unenrolled; invalid, unsafe, missing-companion or inconsistent configured state blocks governed operations. macOS has no legacy one-file enrollment fallback. Offline version-one preparation is normalized to paired version-two storage during native enrollment.

The existing `managed install`, `update`, `rotate`, `status`, export and signed `recover` commands use this source. Writes require a separately elevated root CLI; the dashboard stays unelevated. Independent bootstrap/recovery keys, policy signatures, expiry, exact recovery preimages and the accepted revision floor retain their existing protocol rules. An intact acceptance record raises the recovery floor after primary corruption. Missing/corrupt accepted history cannot be silently reset.

Foreground inputs require protected canonical ancestors, a protected regular leaf and protected neighboring objects. For an enclosing `.app`, the complete outer bundle is inspected, including neighboring Frameworks and helper directories. Links, special files and mutation grants are refused. Inspection is bounded to 4,096 entries, 32 directory levels and 512 MiB of aggregate file content per tree. Executable leaves require a native 64-bit Mach-O executable loader header, or a canonical 32/64-bit universal architecture table containing the native CPU. Slices, CPU/subtype identity, alignment, overlap, command counts/lengths, segment file ranges and entry-header presence are bounded and checked. Debug/symbol tables are not expanded. This is format admission, separate from the signed policy's exact SHA-256 and native ownership/ACL checks; it does not certify publisher signatures, hardware CPU subfeatures, dynamic-library closure or vendor behavior. Interpreter assets remain unavailable for managed launch.

A managed child receives only `PATH=/usr/bin:/bin:/usr/sbin:/sbin`, `LANG=C`, `LC_ALL=C` and `TZ=UTC`. No caller HOME, DYLD, shell, language-runtime or application-state selectors are inherited. This environment is not a vendor process sandbox. Authorization monitoring stops owned work when the policy identity changes, expires or becomes unreadable/unsafe.

## Isolated filesystem exhaustion acceptance

`scripts/test-darwin-storage.py` is restricted to an explicitly opted-in ordinary-user GitHub-hosted Mac job. It creates one new bounded 512 MiB APFS image, retains the installed tool help, validates command results and exact image/device association, enables ownership only for that image, and invokes the guarded root test on its private volume. The native fixture independently requires a canonical receipt/capsule, the exact associated device, local ownership-enabled APFS, a capacity below 1 GiB and a filesystem distinct from the host before creating filler data. Neither the system volume nor the fixed machine-policy source is a pressure target.

Eight cases attempt install/update/rotation/recovery at primary and acceptance record creation. They require actual ENOSPC, unchanged active policy/history and blocked damaged state, a successful explicit signed retry after deleting only the tracked filler, and preservation of partial or independently changed record bytes and retained stage identities. Exclusively owned fully written aborted objects may be cleaned under the existing exact-preimage rules. The image is never grown or remounted to make a case pass. Cleanup rebinds the device to its owned image, uses ordinary detach, refuses busy/unidentified devices and never recursively removes a mounted path. Public `darwin-storage-fault-check-ARCH` records retain source/host/compiler, case outcomes and detach/image-removal results; images and private signing keys are excluded.

A configured test is not passing evidence. Inspect the exact native source-bound results. An APFS disk image does not qualify hardware I/O errors, physical power loss, every filesystem/OS, unrelated application storage or complete deployment. [Apple's disk-image guide](https://support.apple.com/en-gb/guide/disk-utility/-dskutl11888/mac) describes APFS image support; CLI syntax and mount metadata are checked against each actual hosted system.
