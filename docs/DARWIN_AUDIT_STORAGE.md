# Darwin audit storage and journal foundation

macOS amd64/arm64 still reports local audit recording as unsupported. This internal foundation admits private storage objects and provides a private journal unit. Actor-key enrollment, the local producer adapter, historical export and public recorded commands remain unimplemented. Signed `requireProfileAudit` therefore continues to refuse unrecorded profile mutations on macOS. No readiness gate is promoted.

The directory scope retains native descriptors from `/` through an existing private directory. It bounds canonical UTF-8 paths to 1,023 bytes, 128 components and 255 bytes per component. Symlinks, ambiguous components and unsafe ancestors refuse. Each operation rechecks the executing UID/GID snapshot, every retained parent/name binding, full native device/inode identity and filesystem observations. Root and the executing account remain trusted.

Ancestors must belong to root or the executing UID, prevent unrelated writes and pass extended-ACL integrity checks. The scope accepts only local APFS with ownership enabled and refuses observed automounted filesystems. Protected System/Data volume transitions remain possible; each component retains its own filesystem identity. Ancestor flags have an explicit allowlist. The protective `SF_NOUNLINK` flag is admitted on already trusted ancestors: [Apple defines it as preventing removal and rename](https://developer.apple.com/documentation/system/fileflags/systemnounlink), which grants no read/write authority. Firmlinks remain restricted to root ownership. Final private objects require zero file flags.

The final directory requires the executing UID, exact `0700` and an absent or validated empty extended ACL. Only `.actor-key` and `events.journal` are admitted as children. Before opening an existing child, metadata must identify a regular, single-link, bounded, same-owner, same-device file with exact `0600` and permitted flags. Held-handle checks then verify the filesystem, empty ACL and name binding. Size and timestamps are observations around I/O, rather than a frozen baseline across authorized writes.

Exclusive creation returns a read/write handle. Only the newly created, still-empty object may have its ACL reset and mode set before payload is written. Existing ACLs, permissions, files and partial initialization are never repaired or removed. Directory handles belong to the scope; returned data handles belong to the caller. Methods serialize with scope close. The journal borrows this scope, owns its single data descriptor and must close before its caller closes the scope.

The journal holds a nonblocking exclusive advisory `flock` on the actual data file until its owning close. Shared locks are available for a future checked historical reader. It uses no sidecar or duplicated lock owner. Journal and directory mutexes remain held through payload I/O, native sync requests and exact readback; close waits for an active operation. Directory bindings, file state and executing credentials are rechecked around I/O.

Creation writes the exact genesis checkpoint. Append acknowledges only after an exact write, file and parent-directory `fsync` followed by `F_FULLFSYNC`, and verification of the complete candidate stream against the expected checkpoint. A refused full-sync request has no fallback. A short write, sync failure or failed readback makes that journal instance unavailable and returns no checkpoint. Existing bytes are preserved without truncation, repair or automatic adoption. Reopening requires independently supplied exact genesis and head checkpoints; a complete unacknowledged tail can only be reconciled against those endpoints.

Cancellation is cooperative. A canceled request checked before mutation does not write. Once a write starts, sync and readback finish synchronously so the result reflects the actual commit attempt; cancellation does not abandon a native call or close a descriptor underneath it. This unit validates checkpoint structure and stream consistency. It does not enroll an actor key or authenticate a producer against the current build.

Apple defines dataless files as placeholders that may materialize when accessed and firmlinks as protected System/Data transitions. [Apple's file-flag definitions](https://github.com/apple/swift-system/blob/main/Sources/System/FileSystem/FileFlags.swift) inform the admission checks. Pre-open refusal of marked placeholders and postlookup APFS checks do not establish a no-hydration or no-automount guarantee for metadata lookup.

Owned native tests require `ACCESSWEAVER_DISPOSABLE_DARWIN_AUDIT_TEST=1` in a GitHub-hosted Actions process before any home-directory fixture is created. The native unit and CGO-free steps opt in explicitly; ordinary local test runs skip this fixture. These tests exercise ordinary-user creation/reopening, exact identity bindings, invalid paths/names, unsafe modes/ACLs, aliases, special files and preservation after refusals. CI runs these source-built tests in the native unit suite and the explicit CGO-free Darwin trust step. Cross-compilation is not native acceptance. Admission refusals carry only closed source-defined rejection codes. The public error string and storage-error identity stay generic; the hosted fixture can print a fixed code without paths, account IDs, native flag values or raw errors. Codes identify a failed check and do not establish a repair or successful qualification. Both native architecture jobs must pass for the actual source before accepting these scenarios. Journal tests add real independent-process shared/exclusive contention, last-owner lock release, controlled interruption before sync, capacity, close races and cancellation. Synthetic committer failures cover partial/short writes, false acknowledgments, readback mismatch and a refused sync request; they do not inject a native kernel or device sync failure. Child control is bounded, signals precede the sole wait owner, and an unconfirmed child exit preserves its fixture. Distinct-account access denial, unsupported-volume behavior and native fault injection still need their own qualification. The native macOS jobs for the earlier `CheckEmptyACL` prerequisite both passed in [the f271e1f source CI run](https://github.com/Yunushan/accessweaver/actions/runs/41959655234), whose two Windows command jobs failed. That result does not qualify later storage code.

The earlier storage admission scenarios passed on both native macOS architectures in [the 48ed77a source CI run](https://github.com/Yunushan/accessweaver/actions/runs/42062107802); its two Windows command jobs failed. That result predates this journal unit. The journal requires fresh native acceptance on both architectures, including actual file/directory full-sync and independent-process locking. Remaining work includes actor-key and local producer integration, historical output aliases, actual ordinary-process CLI/UI/foreground-run and signed-policy acceptance on both architectures. Successful OS sync requests will still require separate reboot/power-loss and packaged managed-endpoint qualification.
