# Darwin audit storage foundation

macOS amd64/arm64 still reports local audit recording as unsupported. This internal foundation admits private storage objects; it does not implement a journal, actor-key enrollment, historical export or public recorded commands. Signed `requireProfileAudit` therefore continues to refuse unrecorded profile mutations on macOS. No readiness gate is promoted.

The directory scope retains native descriptors from `/` through an existing private directory. It bounds canonical UTF-8 paths to 1,023 bytes, 128 components and 255 bytes per component. Symlinks, ambiguous components and unsafe ancestors refuse. Each operation rechecks the executing UID/GID snapshot, every retained parent/name binding, full native device/inode identity and filesystem observations. Root and the executing account remain trusted.

Ancestors must belong to root or the executing UID, prevent unrelated writes and pass extended-ACL integrity checks. The scope accepts only local APFS with ownership enabled and refuses observed automounted filesystems. Protected System/Data volume transitions remain possible; each component retains its own filesystem identity. Ancestor flags have an explicit allowlist. The protective `SF_NOUNLINK` flag is admitted on already trusted ancestors: [Apple defines it as preventing removal and rename](https://developer.apple.com/documentation/system/fileflags/systemnounlink), which grants no read/write authority. Firmlinks remain restricted to root ownership. Final private objects require zero file flags.

The final directory requires the executing UID, exact `0700` and an absent or validated empty extended ACL. Only `.actor-key` and `events.journal` are admitted as children. Before opening an existing child, metadata must identify a regular, single-link, bounded, same-owner, same-device file with exact `0600` and permitted flags. Held-handle checks then verify the filesystem, empty ACL and name binding. Size and timestamps are observations around I/O, rather than a frozen baseline across authorized writes.

Exclusive creation returns a read/write handle. Only the newly created, still-empty object may have its ACL reset and mode set before payload is written. Existing ACLs, permissions, files and partial initialization are never repaired or removed. Directory handles belong to the scope; returned data handles belong to the caller. Methods serialize with scope close, and a future journal must retain the scope and verify file state around its own serialized data I/O.

Apple defines dataless files as placeholders that may materialize when accessed and firmlinks as protected System/Data transitions. [Apple's file-flag definitions](https://github.com/apple/swift-system/blob/main/Sources/System/FileSystem/FileFlags.swift) inform the admission checks. Pre-open refusal of marked placeholders and postlookup APFS checks do not establish a no-hydration or no-automount guarantee for metadata lookup.

Owned native tests require `ACCESSWEAVER_DISPOSABLE_DARWIN_AUDIT_TEST=1` in a GitHub-hosted Actions process before any home-directory fixture is created. The native unit and CGO-free steps opt in explicitly; ordinary local test runs skip this fixture. These tests exercise ordinary-user creation/reopening, exact identity bindings, invalid paths/names, unsafe modes/ACLs, aliases, special files and preservation after refusals. CI runs these source-built tests in the native unit suite and the explicit CGO-free Darwin trust step. Cross-compilation is not native acceptance. Admission refusals carry only closed source-defined rejection codes. The public error string and storage-error identity stay generic; the hosted fixture can print a fixed code without paths, account IDs, native flag values or raw errors. Codes identify a failed check and do not establish a repair or successful qualification. Both native architecture jobs must pass for the actual source before accepting these scenarios. Distinct-account access denial, unsupported-volume behavior and native fault injection still need their own qualification. The native macOS jobs for the earlier `CheckEmptyACL` prerequisite both passed in [the f271e1f source CI run](https://github.com/Yunushan/accessweaver/actions/runs/41959655234), whose two Windows command jobs failed. That result does not qualify later storage code.

Remaining work includes data-file locks, complete journal/producer contracts, full-sync error handling, historical output aliases, actual ordinary-process CLI/UI/foreground-run and signed-policy acceptance on both architectures. Successful OS sync requests will still require separate reboot/power-loss and packaged managed-endpoint qualification.
