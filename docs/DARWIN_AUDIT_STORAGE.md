# Darwin audit storage and journal foundation

macOS amd64/arm64 selects the protected Darwin local-recording backend on local APFS. Private storage, journal, actor-key/current-producer and historical-export scenarios passed native unit, race and CGO-free tests on both architectures for [source 4ce5348](https://github.com/Yunushan/accessweaver/actions/runs/42072467110). The public command candidate still requires ordinary-process CLI/UI/foreground-run and signed-policy qualification. Signed `requireProfileAudit` continues to refuse unrecorded profile mutations. No readiness gate is promoted.

The directory scope retains native descriptors from `/` through an existing private directory. It bounds canonical UTF-8 paths to 1,023 bytes, 128 components and 255 bytes per component. Symlinks, ambiguous components and unsafe ancestors refuse. Each operation rechecks the executing UID/GID snapshot, every retained parent/name binding, full native device/inode identity and filesystem observations. Root and the executing account remain trusted.

Ancestors must belong to root or the executing UID, prevent unrelated writes and pass extended-ACL integrity checks. The scope accepts only local APFS with ownership enabled and refuses observed automounted filesystems. Protected System/Data volume transitions remain possible; each component retains its own filesystem identity. Ancestor flags have an explicit allowlist. The protective `SF_NOUNLINK` flag is admitted on already trusted ancestors: [Apple defines it as preventing removal and rename](https://developer.apple.com/documentation/system/fileflags/systemnounlink), which grants no read/write authority. Firmlinks remain restricted to root ownership. Final private objects require zero file flags.

The final directory requires the executing UID, exact `0700` and an absent or validated empty extended ACL. Only `.actor-key` and `events.journal` are admitted as children. Before opening an existing child, metadata must identify a regular, single-link, bounded, same-owner, same-device file with exact `0600` and permitted flags. Held-handle checks then verify the filesystem, empty ACL and name binding. Size and timestamps are observations around I/O, rather than a frozen baseline across authorized writes.

Exclusive creation returns a read/write handle. Only the newly created, still-empty object may have its ACL reset and mode set before payload is written. Existing ACLs, permissions, files and partial initialization are never repaired or removed. Directory handles belong to the scope; returned data handles belong to the caller. Methods serialize with scope close. The journal borrows this scope, owns its single data descriptor and must close before its caller closes the scope.

The journal holds a nonblocking exclusive advisory `flock` on the actual data file until its owning close. Historical export holds a shared lock on its checked read-only data handle. It uses no sidecar or duplicated lock owner. Journal and directory mutexes remain held through payload I/O, native sync requests and exact readback; close waits for an active operation. Directory bindings, file state and executing credentials are rechecked around I/O.

Creation writes the exact genesis checkpoint. Append acknowledges only after an exact write, file and parent-directory `fsync` followed by `F_FULLFSYNC`, and verification of the complete candidate stream against the expected checkpoint. A refused full-sync request has no fallback. A short write, sync failure or failed readback makes that journal instance unavailable and returns no checkpoint. Existing bytes are preserved without truncation, repair or automatic adoption. Reopening requires independently supplied exact genesis and head checkpoints; a complete unacknowledged tail can only be reconciled against those endpoints.

Cancellation is cooperative. A canceled request checked before mutation does not write. Once a write starts, sync and readback finish synchronously so the result reflects the actual commit attempt; cancellation does not abandon a native call or close a descriptor underneath it. This unit validates checkpoint structure and stream consistency. It does not enroll an actor key or authenticate a producer against the current build.

The local adapter exclusively initializes an empty private directory with a random 32-byte actor key in the fixed versioned frame, using the same file/parent full-sync contract. It verifies exact key bytes before and after journal initialization and closes both owners before returning the genesis checkpoint. Existing or partial initialization is refused and preserved. Key reads require exact framing, two matching bounded reads and stable file/name metadata; buffers are cleared, including a returned key after a late close or binding failure. The adapter owns the scope and closes the journal first.

Opening and successful append/snapshot operations compare the complete enrolled Producer with metadata derived again from the protected key, executing OS principal and current build. A changed key or producer makes the adapter unavailable. If a change is detected after a completed append, it returns no checkpoint and preserves the written tail with the previous acknowledged in-memory endpoint. The actor key pseudonymizes the executing principal; it provides no signature, human attribution or collector acknowledgment.

Historical export verifies independently retained genesis/head checkpoints under a shared data lock. It does not read key contents, compare the historical Producer with the current build, sync or repair source storage. Direct `*os.File` output identities are checked against the journal and a metadata-only, nofollow lookup of the optional actor-key name; missing or malformed historical keys do not prevent unrelated output. Every source handle and lock closes successfully before the first output byte. Short or failed output returns a generic output error without retry; partial output must be inspected. Callers remain responsible for checkpoint input aliases and writers or pipes that forward into protected files. Cancellation is cooperative and cannot bound a blocked native or output operation.

Apple defines dataless files as placeholders that may materialize when accessed and firmlinks as protected System/Data transitions. [Apple's file-flag definitions](https://github.com/apple/swift-system/blob/main/Sources/System/FileSystem/FileFlags.swift) inform the admission checks. Pre-open refusal of marked placeholders and postlookup APFS checks do not establish a no-hydration or no-automount guarantee for metadata lookup.

Owned native tests require `ACCESSWEAVER_DISPOSABLE_DARWIN_AUDIT_TEST=1` in a GitHub-hosted Actions process before any home-directory fixture is created. The native unit and CGO-free steps opt in explicitly; ordinary local test runs skip this fixture. Native audit tests also run with the race detector in CI; release verification mirrors the guarded unit, race and CGO-free coverage. These tests exercise ordinary-user creation/reopening, exact identity bindings, invalid paths/names, unsafe modes/ACLs, aliases, special files and preservation after refusals. CI runs these source-built tests in its native unit, race and explicit CGO-free Darwin trust steps. Cross-compilation is not native acceptance. Admission refusals carry only closed source-defined rejection codes. The public error string and storage-error identity stay generic; the hosted fixture can print a fixed code without paths, account IDs, native flag values or raw errors. Codes identify a failed check and do not establish a repair or successful qualification. Both native architecture jobs must pass for the actual source before accepting these scenarios. Journal tests add real independent-process shared/exclusive contention, last-owner lock release, controlled interruption before sync, capacity, close races and cancellation. Synthetic committer failures cover partial/short writes, false acknowledgments, readback mismatch and a refused sync request; they do not inject a native kernel or device sync failure. Child control is bounded, signals precede the sole wait owner, and an unconfirmed child exit preserves its fixture. Distinct-account access denial, unsupported-volume behavior and native fault injection still need their own qualification. The native macOS jobs for the earlier `CheckEmptyACL` prerequisite both passed in [the f271e1f source CI run](https://github.com/Yunushan/accessweaver/actions/runs/41959655234), whose two Windows command jobs failed. That result does not qualify later storage code.

A separate [ordinary command fixture](../scripts/test-darwin-audit-commands.sh) runs on fresh hosted Intel and Apple Silicon Macs after each host passes its own CGO-free audit/trust and audit race tests. Each architecture's tests run independently when another runner is unavailable; release packaging still requires the full verification matrix and both command jobs. Guarded source-test setup enrolls a temporary protected signed policy; every recorded CLI, loopback desktop and inert-engine operation runs as an ordinary process with no additional groups. Nine operation groups cover required-audit admission, import, desktop edits, historical and recorded export, output aliases, capacity, foreground completion and cancellation. Workspace cleanup is an independent required result. Private command output is bounded and discarded; only fixed bootstrap/case failures are emitted, with no new private artifact collection. First-failure alias diagnostics use 124 source-defined case labels and 24 closed check labels; unknown or inconsistent diagnostic tuples refuse before reporting. Recorded-command authority references include the fixed native policy pair and coordination file, without opening them for payload I/O. Uncertain process completion or changed owned objects preserve fixture state and fail qualification. Inert lifecycle success does not establish real routing, external vendor behavior or installed-endpoint acceptance.
The earlier storage admission scenarios passed on both native macOS architectures in [the 48ed77a source CI run](https://github.com/Yunushan/accessweaver/actions/runs/42062107802); its two Windows command jobs failed. That result predates this journal unit. The 4ce5348 native unit, race and CGO-free audit tests passed on both architectures, including actual file/directory full-sync, independent-process locking, producer drift, key preservation and output aliases. This configured source-fixture result does not qualify public commands or an installed endpoint. Remaining work includes public command integration and actual ordinary-process CLI/UI/foreground-run and signed-policy acceptance on both architectures. Successful OS sync requests will still require separate reboot/power-loss and packaged managed-endpoint qualification.
