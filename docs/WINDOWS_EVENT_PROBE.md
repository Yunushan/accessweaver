# Hosted controlled firewall event probe

The Windows installer workflow adds a separate opted-in native diagnostic probe before the original installer baseline. It creates one fresh nonce-named disabled rule in the local PersistentStore, checks that the normal comparison detects only that added firewall identity, invokes the existing isolated failure-diagnostic adapter and removes only its freshly revalidated owned rule. It then requires the entire original selected service/firewall/DNS snapshot to match exactly. No installer is executed by this probe.

Microsoft documents [disabled-rule behavior](https://learn.microsoft.com/en-us/powershell/module/netsecurity/new-netfirewallrule?view=windowsserver2025-ps) and [input-object removal](https://learn.microsoft.com/en-us/powershell/module/netsecurity/remove-netfirewallrule?view=windowsserver2025-ps). Disabled rules do not actively filter traffic. Creation and lookup explicitly select PersistentStore. Cleanup checks the nonce tags, captured CIM identity and rule/filter fingerprints, then removes through the revalidated input object. Name and InstanceID do not establish an unforgeable creation incarnation: a same-admin identical replacement remains inside the OS trust boundary, and ownershipComparisonAtomic stays false. Unknown publication, changed identity/configuration, unrelated drift or ambiguous cleanup fails and preserves uncertain state; the fixture never restores, deletes or rebases unrelated rules.

The probe uses an owned private temporary capsule for the exact existing sanitized process helper. Its marker, path and reparse checks must succeed before capsule cleanup. All creation attempts and confirmed ownership/removal are distinguished. Native scripts require the declared repository, exact clean source, matching elevated hosted Windows architecture and explicit workflow opt-in. They are not a local desktop test command. Local validation uses synthetic PowerShell and Python tests only.

The report separates adapterCalled, queryAttempted and nativeReadCompleted. The latter is true only for captured metadata; a missing/disabled/unreadable log or incomplete bounded child can produce unavailable without a fabricated event match. The fixture never enables a log channel or audit policy. Query time/event/XML/field/record caps and exact identity fingerprints remain those of the existing adapter. Matching records are optional; no basename, named field or successful probe establishes process origin or explains historical installer drift.

Before attestation, an independent Python validator checks the closed report shape, bounded descriptor read, exact source hashes, controlled-only addition, full baseline restoration, cleanup flags, truthful captured/unavailable status, seven-digit UTC windows and hash-only event fields. The report is a separate attested subject with its own retained provenance bundle. The original five installer/SBOM/native-report subjects and schema-11 preservation assertions remain unchanged. A failed probe prevents the installer step; bounded failure evidence is still retained.

Source and synthetic tests prepare the new path. Actual exact-source hosted results are still required, including captured versus unavailable status and owned cleanup. A probe that safely reports unavailable is not proof of a completed native log read. The original installer suite, publisher signing, reboot/power-loss, managed endpoints and all remaining readiness gates stay separate. No readiness percentage is promoted.

See [installer diagnostics](WINDOWS_INSTALLER_DIAGNOSTICS.md) for event privacy, source binding and original failure evidence.
