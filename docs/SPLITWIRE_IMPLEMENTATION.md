## Cross-process storage follow-up

Profile reads, saves, deletion and initial seeding now use OS file locks shared across cooperating processes on the same OS/local filesystem. Foreground CLI controllers and imports also claim the data root before seeding. Contention has a five-second acquisition limit, HTTP 503/`Retry-After: 1`, and request cancellation prevents a queued mutation from running after its caller cancels.

With Go 1.27.3, the Windows/amd64 full Go suite and vet pass, followed by final regression checks for the changed packages. The Ubuntu WSL2 Linux/amd64 full suite, vet and race detector also pass. Native subprocess tests verify normal/forced exit releases locks and six independent saves of one reviewed revision produce exactly one winner. The existing 45 JavaScript tests and 47 PowerShell contracts still pass. Local logs and candidate artifacts are retained under ignored `build/readiness-locking/`.

The current unsigned Windows candidate can run `version --json` successfully. The real Linux controller smoke test also passes all 11 checks, including duplicate-owner exclusion, proxy-independent private bootstrap, launcher cleanup and import after graceful shutdown. These observations do not establish publisher trust or managed networking qualification.

These checks do not certify power-loss durability, recovery from filesystem corruption, backup/restore, Windows/WSL shared-store interoperability or networking/traffic behavior. Current cross-process behavior still needs native macOS/BSD execution evidence. The cross-user Linux session script was not run locally because the WSL account requires interactive sudo authentication; no account or sudo policy was changed. Broader readiness gates remain open.

Reboot persistence, Windows 10 compatibility, WireSock handshakes, ProxiFyre TCP/UDP app interception, Discord voice, QUIC/STUN, IPv6 tunnel traffic, strategy effectiveness on each ISP, and cancellation during vendor installers require additional native evidence before a full-parity claim.
