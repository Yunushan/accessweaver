# Disposable WireGuard test peer

This optional test module is separate from AccessWeaver's core. It uses the official WireGuard-Go userspace netstack to serve an HTTP fixture and UDP echo over IPv4 and IPv6. It does not create a host tunnel, change routes/DNS, install a driver, register a WARP account or use real VPN credentials.

The patched fixture dependencies require Go 1.26 or later; CI uses Go 1.27.4. Build with `scripts/build-windows-fixtures.ps1`. Run the resulting binaries only inside the disposable test VM. `ACCESSWEAVER_TEST_VM=1` is required. `wgpeer self-test DIRECTORY` checks the fixture itself using two userspace peers; `wgpeer serve DIRECTORY` writes an ephemeral client configuration, a readiness record and traffic counters. Keep the private client configuration inside the guest. Only counters belong in public reports.

The default WireGuard bind listens on a dynamically allocated UDP port in the guest. The client configuration uses its loopback endpoint. No host firewall rule or host listener is required. The reserved test destinations are `198.51.100.1` and `fd42:6177::1`, TCP port 8080 and UDP port 7000.

Implementation API reference: [WireGuard's official netstack server example](https://git.zx2c4.com/wireguard-go/tree/tun/netstack/examples/http_server.go). The WireGuard revision and all transitive module checksums are pinned in this module. The build script copies dependency license notices into the private test bundle; this fixture is not included in core release archives.

Known-vulnerability checks cover Linux/amd64 and Windows/amd64 source configurations. Dependencies are updated through the fixture's separate module; the core module is unchanged. A source scan or compilation does not requalify the fixture's handshake/traffic behavior: rerun its self-test in the disposable guest after dependency updates. The fixture pins `golang.org/x/crypto v0.58.1-0.20261009181718-2f1f834330b2`, the exact upstream commit identified by [GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932). The latest tagged v0.58.0 still contains the obsolete OpenPGP tree. The selected checksum-verified module removes that tree; all 337 remaining files match v0.58.0. Its Go requirement and module-graph dependencies are unchanged. The separate unsafe OpenPGP module is not added or used.

The existing CI vulnerability job now runs `scripts/fixture_qualification.py` in a fresh GitHub-hosted Linux AMD64 guest. The explicit `fixture-dependencies` manual scope selects only that job. A hosted-runner/ordinary-user/native-SDK guard precedes execution; the VM opt-in is supplied only to the fixture child. Both normal and race binaries perform the existing TCP/UDP IPv4/IPv6 userspace-peer self-test. Reports require recent handshake evidence, nonzero traffic counters, clean source identity, exact module/binary identities, absence of the parent OpenPGP directory, and zero affected or module-only advisories in both configured source targets. Windows peer/probe binaries are inspected but not executed. Fixture SBOM schema checks remain part of the job.

Only a closed `status.json` is published for self-test evidence: source/binary hashes, fixed target/mode/check labels, numeric counters and advisory summaries. Private keys, configurations, native paths, exact handshake timestamps, raw child/scanner output and credentials are excluded. Failure, timeout, excessive output, incomplete evidence or a source change prevents success. This fixture evidence does not qualify installed WireGuard/WireSock drivers, application routing, DNS restoration, the full desktop matrix, physical durability or production readiness.

The [f212225 qualification receipt](../../../docs/qualification/f212225d1d35-wireguard-fixture-crypto.json) records the first-attempt hosted Linux job passing: both normal/race modes complete TCP/UDP IPv4/IPv6 exchanges with fresh handshakes and nonzero counters; both configured advisory graphs have zero affected and zero module-only findings. Windows peer/probe compile identities and fixture SBOM schema checks pass. The provider ZIP digest, fixed schema, source and binary identities are verified. The obsolete parent OpenPGP tree is absent; the core runtime and root module are unchanged. Installed vendor and wider platform qualification remain separate.
